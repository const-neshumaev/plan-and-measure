# Протокол обмена с дальномером

Единственный источник истины о протоколе. Всё, что здесь не подтверждено измерениями, помечено явно.

## Дисклеймер

Протокол восстановлен независимо: наблюдением за BLE-обменом с собственным прибором (см. `docs/protocol-research/experiments.md`). Официальной спецификации производителя не существует; этот документ не является его публикацией, не одобрен им и не гарантирует, что описанное поведение совпадёт на других прошивках и моделях.

Здесь нет кода прошивки, кода приложения производителя и иных охраняемых материалов — только наблюдаемые факты обмена. Материалы предоставляются «как есть», без гарантий пригодности для конкретной цели. Использование протокола может регулироваться применимым правом и условиями производителя; авторы документа за это не отвечают.

Названия моделей и брендов принадлежат их правообладателям и упоминаются только для обозначения совместимости.

Статус: **формат кадров подтверждён для всех семи режимов единиц: метры с тремя знаками, метры с двумя знаками, футы, футы-дюймы (`ftin`), футы-дюймы с кавычками (`' "`), дюймы с точкой и дюймы с дробью. Режимы площади/объёма/Пифагора по BLE не передаются — приходят только отдельные расстояния. Кадры ошибок и выхода за диапазон не наблюдались — TBD.**

MAC-адрес случайный и может измениться после выключения прибора. Идентифицировать устройство нужно по имени `Sniper 80` и/или сервису `0xCBBB`.

## 2. Транспорт

| Параметр | Значение |
|---|---|
| Тип | BLE GATT |
| Сопряжение (bonding) | не требуется (подтверждено) |
| Handshake | **не требуется**: данные приходят после записи CCCD, без записей в устройство |
| MTU | 23. Запрос 517 возвращает `status=0`, `MTU=23` |
| Реклама | Flags + 16-bit Service UUID `0xCBBB` + Complete Local Name `Sniper 80` |
| Адрес | random static, не использовать как постоянный идентификатор |

## 3. GATT-карта

Полный дамп GATT снимается приложением и хранится локально; в публичный репозиторий дампы не входят.

| Сервис | Характеристика | Properties | Назначение |
|---|---|---|---|
| `0x1800` Generic Access | `0x2A00` Device Name | READ WRITE | стандартная |
| | `0x2A01` Appearance | READ | стандартная |
| | `0x2A04` Preferred Connection Parameters | READ | стандартная |
| | `0x2AA6` (Central Address Resolution) | READ | стандартная |
| `0x1801` Generic Attribute | `0x2A05` Service Changed | INDICATE | стандартная |
| `0xCBBB` (custom) | `0xCBB1` | READ WRITE WRITE_NR NOTIFY INDICATE | **основной канал: измерения приходят в NOTIFY** |

`0xCBB1` имеет CCCD `0x2902`, а также дескрипторы `0x2900` (Characteristic Extended Properties) и `0x2903` (Server Characteristic Configuration) — назначение TBD.

## 4. Формат кадра

| Свойство | Значение |
|---|---|
| Длина | 16 байт |
| Кодировка | ASCII |
| Заголовок | `D` (`0x44`) — расстояние (наблюдался во всех режимах) |
| Число | десятичная строка; положение точки зависит от режима единиц |
| Единица | текстовая: `m` (3 знака), `m` (2 знака), `ft`, `ftin`, `in`; в режиме `' "` единицы нет |
| Дробь | отдельное поле после единицы в трёх «дробных» режимах |
| Хвост | пробелы `0x20` до 16 байт |

Устройство отправляет **содержимое дисплея**: отсюда фиксированная длина 16 и выравнивание пробелами.

### 4.1 Режимы единиц

В цикле `UNITS` семь режимов. Порядок по наблюдениям 2026-11-17 (точное место `m` с двумя знаками в кольце отдельно не проверялось):

`m` (3 знака) → `m` (2 знака) → `ft` → `ftin` → `' "` → `in` (точка) → `in` (дробь) → `m` (3 знака).

Миллиметров в цикле нет.

| Режим | Пример кадра | Значение | Как читать кадр |
|---|---|---|---|
| `m`, 3 знака | `D3.690m` | `3.690 m` | число = метры (1:1) |
| `m`, 2 знака | `D40.61m` | `4.061 m` | число / 10 |
| `ft` | `D119.61ft` | `11.961 ft` | число / 10 |
| `ftin` | `D11.08ftin  3/16` | `11 ft 08 in 3/16` | `FF.II` + дробь |
| `' "` | `D12'07"     5/16` | `12 ft 07 in 5/16` | `F'II"` + дробь |
| `in`, точка | `D?987.9in` | `159.879 in` | число / 100 |
| `in`, дробь | `D32000in    5/ 8` | `32 5/8 in` | целое + `000` + дробь |

На дисплее число знаков после точки может быть меньше, чем в нормализованном значении: кадр и декодер сохраняют три знака для метров, футов и дюймов, а дисплей показывает столько, сколько помещается. Для хранения используется точность кадра.

### 4.2 Сдвиг десятичной точки

В трёх режимах прибор печатает точку не там, где показывает:

| Режим | Кадр | Значение | Сдвиг |
|---|---|---|---|
| `m`, 2 знака | `D40.61m` | `4.061 m` | вправо на 1 разряд (÷10) |
| `ft` | `D119.61ft` | `11.961 ft` | вправо на 1 разряд (÷10) |
| `in`, точка | `D?987.9in` | `159.879 in` | вправо на 2 разряда (÷100) |

Проверено на одной и той же точке 2026-11-17:

| Дистанция | Кадры |
|---|---|
| 0,828 м | `D0.828m`, `D8.28m`, `D3259.8in`, `D32000in    5/ 8` |
| 4,061 м | `D4.061m`, `D40.61m` |
| 159,879 дюйма | `D?987.9in`, `D?9000in    7/ 8` (159 7/8 = 159,875) |

Похоже на ошибку форматирования прошивки: внутреннее значение имеет три знака после точки, но в кадре точка ставится правее. Декодер делит на 10 или 100.

### 4.3 Упакованные старшие цифры

Когда числовое поле не помещается в кадр, прошивка упаковывает **две первые цифры** в один символ: код символа равен `'0' + n`, где `n` — первые две цифры. Поэтому `:` — это 10, `>` — 14, `?` — 15, `F` — 22.

| Кадр | Как читать |
|---|---|
| `D:531.3in` | `10` + `531.3` = 10531.3 → 105,313 in |
| `D>9000in    1/16` | `14` + `9000` = 149000 → 149 1/16 in |
| `D?9000in    7/ 8` | `15` + `9000` = 159000 → 159 7/8 in |
| `D?8000in    7/16` | `15` + `8000` = 158000 → 158 7/16 in |
| `D?987.9in` | `15` + `987.9` = 15987.9 → 159,879 in |
| `DF625.7in` | `22` + `625.7` = 22625.7 → 226,257 in |

Это не «ведущая единица»: ранняя версия документа ошибалась. У значений без упаковки (`D4208.6in`, `D3169.2in`) первые цифры обычные. Почему прошивка упаковывает именно при переполнении поля, TBD; правило `'0' + n` подтверждено на десяти значениях.

Для четырёхзначных дюймов (например, `1435 in` на фото) кадр по BLE не пойман; ожидается `>35000in` + дробь при той же упаковке, но это TBD.

### 4.4 Дробная часть

- Дробь всегда сокращённая: `1/2`, `1/4`, `5/8`, `7/8`, `13/16`, `15/16`.
- Формат `N/D`, знаменатель выровнен в два знака: `1/ 8`, `3/16`, `13/16`.
- Поле прижато к правому краю 16 байт, перед ним пробелы.

Примеры: `D5.04ftin   1/ 2`, `D12'07"     5/16`, `D32000in    5/ 8`.

### 4.5 Режим дюймов с дробью

Целое число дюймов дополняется тремя нулями — незанятыми разрядами индикатора:

| Кадр | Дисплей |
|---|---|
| `D32000in    5/ 8` | `32 5/8 in` |
| `D42000in    1/16` | `42 1/16 in` |
| `D52000in    3/ 4` | `52 3/4 in` |
| `D>9000in    1/16` | `149 1/16 in` |
| `D?9000in    7/ 8` | `159 7/8 in` |
| `D>7000in    1/16` | `147 1/16 in` |
| `D?8000in    7/16` | `158 7/16 in` |

Декодер раскрывает упакованные старшие цифры (§4.3), затем отбрасывает три последних нуля числового поля и прибавляет дробь.

Кадр этого режима с нулевой дробью (на фото дисплей показывал `1435 in`) по BLE не пойман. Кадр `D?9000in` старой сессии читается как `159 in` — это согласуется с маркером `159 7/8` для того же места. Для четырёхзначных значений поле шире, поведение TBD.

### 4.6 Что делает приложение

`FrameCodec` приводит кадр к десятичному значению в единице дисплея:

| Режим | Нормализация | Единица хранения |
|---|---|---|
| `m`, 3 знака | как есть | метры |
| `m`, 2 знака | ÷10 | метры |
| `ft` | ÷10 | футы |
| `ftin`, `' "` | футы + (дюймы + дробь) / 12 | футы (десятичные) |
| `in`, точка | ÷100 | дюймы |
| `in`, дробь | целое + дробь | дюймы |

Хранимый текст десятичный, с точностью кадра. Режим `ftin`/`' "` в приложении показывается десятичными футами, а не `11'08" 3/16`: отдельной единицы для футов-дюймов в модели хранения нет.

| Переключение режима | кадра нет | да |
| Переключение единиц | кадра нет | да |
| Пересчёт истории при смене единиц | кадра нет | да |

| Результат объёма | **не передаётся** | да |

| Ошибка измерения / выход за диапазон | кадра не наблюдалось | нет |

### Режимы: как получается результат

В режимах площади/объёма/Пифагора прибор присылает **только отдельные расстояния** (все с префиксом `D`). Итог вычисляется на дисплее прибора и в BLE не попадает. Проверено на сессии 2026-11-14:

| Режим | Присланные расстояния | Показание на дисплее | Проверка |
|---|---|---|---|
| Площадь | 1.421 м, 2.768 м | `3.933` | 1.421 × 2.768 = 3.933 ✓ |
| Объём | 1.726 м, 3.471 м, 1.624 м | `9.729` | 1.726 × 3.471 × 1.624 = 9.729 ✓ |
| Пифагор | 3.384 м, 1.611 м | `2.976` | √(3.384² − 1.611²) = 2.976 ✓ |

Следствие для приложения: режим нужно либо задавать вручную, либо восстанавливать по последовательности измерений. Протокол режим не сообщает.

### Непрерывный режим

Если удерживать кнопку измерения, прибор шлёт один и тот же кадр примерно 3–4 раза в секунду (интервал ~300 мс, иногда ~150 мс). Пример: 12 одинаковых кадров `D0.11ftin   1/ 8` за 3,15 с. Дедупликация — на стороне приложения; протокол повторы не помечает.

## 8. Поведение соединения

- Простой обрыв через ~3,5 минуты без обмена: `status=8 (GATT_CONN_TIMEOUT)`. Второй разрыв — через ~2 минуты после серии кадров.
- Если отойти от телефона во время измерения, связь рвётся; при возврате приложение восстанавливает её само.
- Автопереподключение занимает около 2 секунд, если прибор включён и находится рядом.
- После серии кадров (непрерывный режим) разрыв иногда наступает через ~5 секунд после последнего кадра; гипотеза — прибор уходит в сон после активности. TBD.
- Keepalive не требуется для приёма измерений; на длинных сессиях поведение TBD.
