## 2026-11-14 — E0. Разведка GATT

**Сборка:** Plan & Measure BLE Lab 0.1.0 (debug)
**Условия:** Xiaomi 11T, Android 14; дальномер Instrumax Sniper 80 Plus в Bluetooth-режиме.

**Что делали:**
1. Сканирование без фильтров, выбрано устройство `Sniper 80`.
2. Подключение, запрос MTU 517, обнаружение сервисов, авто-подписка на notify.

**Что наблюдали:**
- MAC скрыт (random static).
- Advertising: `02 01 06 03 03 BB CB 0A 09 53 6E 69 70 65 72 20 38 30` — flags, service UUID `0xCBBB`, Complete Local Name `Sniper 80`.
- MTU: запрос 517 → `MTU=23, status=0`.
- 3 сервиса, 6 характеристик, все `status=0`.
- Подписка: `Service Changed` (indicate) и `0xCBB1` (notify) — успешно, 2 из 2.

**Вывод:**
- факт: канал измерений — `0xCBBB / 0xCBB1`, NOTIFY.
- факт: handshake не нужен, измерения приходят после записи CCCD.
- факт: bonding не требуется.
- не подтверждено: назначение записи в `0xCBB1`.

**Дамп:** локальный (не публикуется)

## 2026-11-14 — E1. Пассивный приём

**Что делали:**
1. Подключились, подождали авто-подписку.
2. Маркер `display ---m`.
3. Три измерения: 1.763 м, 1.479 м, 3.781 м; после каждого — маркер с показанием дисплея.
4. Через ~4 минуты простоя соединение разорвалось.

**Что наблюдали:** после каждого измерения один кадр 16 байт:

```
44 31 2E 37 36 33 6D 20 20 20 20 20 20 20 20 20  |D1.763m         |
44 31 2E 34 37 39 6D 20 20 20 20 20 20 20 20 20  |D1.479m         |
44 33 2E 37 38 31 6D 20 20 20 20 20 20 20 20 20  |D3.781m         |
```

Отключение: `STATE_DISCONNECTED, status=8 (GATT_CONN_TIMEOUT)`.

**Вывод:**
- факт: кадр — ASCII, фиксированные 16 байт, `D` + число с 3 знаками + `m`, добивка пробелами.
- факт: значение совпадает с показанием дисплея 1:1.
- гипотеза: устройство отдаёт содержимое дисплейного буфера.
- не подтверждено: префиксы других режимов, единицы, реакция на включение лазера.

**Дамп:** локальный (не публикуется)

## 2026-11-14 — E3/E4. Единицы, режимы, лазер

**Что делали:**
1. Подключились, авто-подписка.
2. Включили лазер без измерения, поставили маркер `laser on`.
3. Переключили единицы на футы, сделали замер.
4. Вернули метры, режим площади — два замера.
5. Режим объёма — три замера.
6. Пифагор — два замера.

**Что наблюдали:**

| Событие | Кадр |
|---|---|
| Замер, метры | `D1.355m         ` |
| Включение лазера | кадра нет |
| Замер, футы | `D72.60ft        ` |
| Площадь, 1-я сторона | `D1.421m         ` |
| Площадь, 2-я сторона | `D2.768m         ` |
| Объём, три стороны | `D1.726m`, `D3.471m`, `D1.624m` |
| Пифагор, два катета | `D3.384m`, `D1.611m` |

Маркеры с дисплея: площадь `3.933`, объём `9.729`, Пифагор `2.976`.
Проверка: 1.421×2.768 = 3.933; 1.726×3.471×1.624 = 9.729; √(3.384²−1.611²) = 2.976.

**Вывод:**
- факт: единицы передаются текстом (`m`, `ft`), точность — 3 знака для метров, 2 для футов.
- факт: результаты площади/объёма/Пифагора по BLE **не передаются**, приходят только отдельные расстояния с префиксом `D`.
- факт: включение лазера, смена режима и единиц кадров не дают.
- не подтверждено: дюймы/миллиметры, кадры ошибок, совпадение значения с дисплеем в футах (маркер `7.26` против кадра `72.60`).

**Дамп:** локальный (не публикуется)

## 2026-11-14 — E3. Подтверждение футов

**Что делали:** два замера в футах, маркеры с показаниями дисплея.

**Что наблюдали:**

| Дисплей | Кадр |
|---|---|
| `6.76 ft` | `D67.61ft        ` |
| `11.89 ft` | `D118.89ft       ` |

Вместе с прошлой сессией (`7.26 ft` ↔ `D72.60ft`) — три независимых замера.

**Вывод:**
- факт: в футах значение в кадре в 10 раз больше показания дисплея; кадр / 10 = футы.
- гипотеза: ошибка форматирования прошивки — реальное значение имеет точность 0.001 ft, но точка ставится на разряд правее.
- следствие: декодер нормализует футы делением на 10.

**Дамп:** локальный (не публикуется)
