# 0017. Чистить ссылки проекта на удалённые объекты

- Статус: Accepted
- Дата: 2026-11-28

## Контекст

[0015](0015-projects-as-reference-trees.md) решил не чистить ссылки проекта автоматически: ссылка на
объект, которого нет в живых списках, просто не показывается. Причина — отсутствие в списках не
доказывает удаление. Списки измерений и планы читаются независимо от проектов, при старте ещё пусты,
а повреждённый или временно недоступный файл пропускается, хотя сам документ существует. Чистка по
такому признаку могла бы стереть живые ссылки.

При этом ссылки на действительно удалённые объекты копятся в файле проекта. Пользователь не видит
их в дереве и не может убрать. Нужен способ убирать мусор, не рискуя данными при сбое чтения.

## Решение

- Удаление списка измерений или плана убирает ссылки на него из **всех** проектов. Удаление документа
  выполняется первым, а удаление ссылок — после него, по колбэку из ViewModel объекта. Координация
  живёт в UI-слое (`MeasurementsFlow`, `PlansFlow`, `ProjectsFlow`): домены списков и планов
  по-прежнему не знают о проектах.
- Проект умеет удалять объект целиком из контекстного меню строки дерева. Это удаляет файл списка или
  плана и ссылки на него во всех проектах; действие подтверждается диалогом. «Исключить из проекта»
  по-прежнему удаляет только ссылку.
- В меню проекта появляется ручная команда «Удалить ссылки на удалённые объекты». Она предлагается,
  только если у ссылки **нет файла документа** (ни основного, ни `.bak`). Файл, который существует,
  но не читается, в список не попадает: он может ожить после временного сбоя.
- Автоматической чистки по отсутствию в summary нет. Правило 0015 остаётся в силе: сбой чтения не
  должен стирать ссылки.
- Репозитории списков и планов получают проверку существования документа (`hasDocument`), чтобы
  отличать удалённый объект от нечитаемого.

## Последствия

- Удаление объекта теперь трогает два вида документов: файл объекта и документы проектов. Атомарной
  транзакции на несколько файлов нет. Если удаление ссылок не удалось, остаётся скрытая ссылка, и её
  можно убрать ручной командой. Если не удалось удалить документ, ссылки не трогаются.
- Правило 0015 «ссылка остаётся в файле» перестаёт быть безусловным для известного удаления: ссылки
  убираются сразу. Для неизвестных случаев (сбой чтения, старые файлы) остаётся ручная чистка.
- `MeasurementsViewModel.deleteList` и `PlansViewModel.deletePlan` получают необязательный колбэк;
  экраны вызывают удаление через переданное действие, а не напрямую.
- Ручная чистка требует одновременно открытого проекта и живых репозиториев списков и планов; это
  усложняет экран дерева, но не меняет формат документов.
- Счётчики проекта и дерево по-прежнему считают только живые объекты; ручная чистка не меняет это
  правило, а лишь убирает ссылки, которые уже не показывались.

## Альтернативы

- **Оставить ссылки навсегда.** Проще всего, но файл проекта копит мусор, а пользователь не может
  его убрать.
- **Чистить автоматически при открытии по отсутствию в живых списках.** Ровно тот риск, из-за
  которого 0015 отказался от чистки: временный сбой чтения или ещё не завершённая загрузка выглядит
  как удаление.
- **Показывать удалённые ссылки в дереве строками «объект удалён».** Даёт видимость, но засоряет
  дерево и требует придумывать имя вместо отсутствующего документа. Отложено; при необходимости
  добавляется новым ADR.
- **Хранить имя объекта в ссылке**, чтобы показывать удалённые строки. Противоречит 0015: имя берётся
  из живого документа, иначе переименования расходятся между копиями.
