# Plan & Measure

Android-приложение для лазерного дальномера **Instrumax Sniper 80 Plus**. Цель — принимать измерения по Bluetooth, привязывать их к фотографиям и схемам помещения, сохранять проекты.

## Статус

Этап 1 — **исследование протокола**: формат кадров подтверждён для метров и футов, открытые вопросы собраны в `docs/protocol.md`.

Этап 2 — **MVP**: приложение называется `Plan & Measure`, появилось главное меню и каркас разделов. Лабораторный инструмент `Plan & Measure BLE Lab` теперь отдельный пункт меню: он остаётся рабочим инструментом для экспериментов.

Что умеет текущая сборка:

- главное меню с разделами «Измерения», «Проекты», «Съёмка», «Настройки»;
- живой статус подключения к дальномеру на главном экране;
- поиск и подключение дальномера: автоматическое сканирование, подсветка найденного прибора, отключение;
- «Настройки» уже работают: тема (светлая/тёмная) и язык (русский/английский); при первом запуске значения определяются по системным настройкам (если системный язык не поддерживается — английский), затем хранятся явно;
- тема и язык сохраняются между запусками;
- остальные разделы MVP пока показывают демонстрационный контент с пометкой Demo;
- BLE Lab: сканирование BLE-устройств без фильтров (имя, MAC, RSSI, сервисы, manufacturer data, сырой advertising-пакет);
- подключение по GATT, запрос MTU, обнаружение сервисов;
- автоматическая подписка на все notify/indicate-характеристики;
- просмотр GATT-дерева с человекочитаемыми именами известных UUID;
- ручная отправка hex/текста в любую write-характеристику (для поиска handshake-команд);
- журнал всех событий и пакетов с метками, поиском глазами и экспортом в CSV/TXT;
- экспорт дампа GATT-дерева.

Публичного описания протокола Instrumax не существует — он получен экспериментально. Методика описана в `docs/research-plan.md`.

## Требования

- Android Studio (актуальная версия) — она принесёт JDK 17+ и Android SDK.
- Телефон с BLE и Android 7.0+ (проверяем на Xiaomi 11T, Android 14).
- Дальномер с включённым Bluetooth-режимом.
- Для Gradle нужен JDK 17–21. Встроенный в новые версии Android Studio JBR 25 не подходит для Gradle 8.7: в Settings → Build, Execution, Deployment → Build Tools → Gradle выберите Gradle JDK 17/19/21 (можно скачать прямо там).

Отдельно ставить Gradle не нужно: версия зафиксирована в `gradle/wrapper/gradle-wrapper.properties`, wrapper уже в проекте.

### SDK

Проект ожидает Android SDK с установленными `Android SDK Platform 34` и `Android SDK Build-Tools 34.0.0`. Если при открытии Android Studio просит путь к SDK, укажите корень SDK (папку, в которой лежат `platforms`, `build-tools`, `platform-tools`). Затем в SDK Manager установите платформу 34 и Build-Tools 34.0.0 и примите лицензии.

## Сборка

1. Открыть папку проекта в Android Studio.
2. Дождаться Sync: Studio сама скачает Gradle 8.7 и зависимости, при необходимости предложит установить Android SDK Platform 34 и Build Tools.
3. Запустить на телефоне: `Run 'app'`.

Через командную строку (нужны JDK 17–21, Android SDK и env `JAVA_HOME`, указывающий на этот JDK):

```
./gradlew assembleDebug
```

APK появится в `app/build/outputs/apk/debug/`.

## Первый эксперимент (за один вечер)

1. Включить дальномер, включить на нём Bluetooth-режим (обычно отдельная кнопка/пункт меню).
2. Запустить приложение, выдать разрешения и открыть **BLE Lab** в главном меню.
3. Нажать **Start scan**, найти устройство по имени (часто содержит название бренда, модели или похожее) или по RSSI — оно будет самым сильным рядом с телефоном.
4. Нажать **Connect**. Приложение подключится, подпишется на все характеристики и откроет GATT-дерево. Убедиться, что переключатель MTU включён.
5. Перейти на вкладку **Log**, нажать **Marker** и записать: `display 0.000 m, laser off`.
6. Навести дальномер на стену на расстоянии ~1 м, нажать измерение. В логе должны появиться строки `NOTIFY` с hex-байтами.
7. Поставить маркер с фактическим показанием дисплея (`display 1.000 m`) сразу после измерения.
8. Повторить для 2.000 м и 3.456 м (или любых удобных значений).
9. Нажать **CSV**, сохранить файл и прислать его агенту для анализа.

Если после подключения и нажатия кнопки измерения в логе **нет** `NOTIFY` — это важный результат: значит, устройству нужна команда включения. Тогда переходим к экспериментам E4–E5 из `docs/research-plan.md` (ручная отправка команд).

## Структура проекта

```
app/src/main/java/com/planmeasure/
  MainActivity.kt           точка входа, edge-to-edge
  LabViewModel.kt           состояние BLE-сессии и лабораторные сценарии
  ble/
    BleScanner.kt           сканирование
    BleGattClient.kt        GATT-клиент с очередью операций
    BleModels.kt            модели сканирования и GATT
    BleUuids.kt             словарь UUID
    BlePermissions.kt       разрешения Android 12+
    BleUtils.kt             мелкие помощники
    RangefinderDevice.kt    эвристика «это дальномер» для списка устройств
  logging/
    PacketLog.kt            журнал событий и пакетов
    LogExporter.kt          CSV/TXT
    Hex.kt                  hex-кодирование и разбор
  protocol/
    FrameCodec.kt           разбор подтверждённых кадров
  settings/
    AppSettings.kt          модель настроек (тема, язык)
    SettingsStorage.kt      сохранение в SharedPreferences
    SettingsViewModel.kt    состояние настроек и запись
    LanguageResolution.kt   выбор локали и fallback на английский
  ui/
    AppRoot.kt              навигация: меню, разделы MVP, подключение, BLE Lab
    home/HomeScreen.kt      главное меню и статус подключения
    connect/ConnectScreen.kt  поиск и подключение дальномера
    sections/               экраны-заглушки разделов MVP
    lab/
      LabFlow.kt            общий app bar и back-навигация лаборатории
      ScanScreen.kt         список устройств
      DeviceScreen.kt       GATT-дерево, команды, журнал
    components/             общие компоненты
    theme/                  палитра, типографика, формы
app/src/main/res/
  values/strings.xml        английские строки (по умолчанию)
  values-ru/strings.xml     русские строки
```
